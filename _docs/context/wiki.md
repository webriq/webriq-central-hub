# Wiki history and edit safety

Moved verbatim from CLAUDE.md. Read before working in this area.

- **Wiki history + edit safety** (migration 151 / task 402, **written not applied**; builds on `wiki_pages`/`wiki_page_versions` from migration 149). Two counters on `wiki_pages`: `version` keeps task 399's **publish-only** meaning (the `v{n}` badge), while `revision` bumps on **every** content/status save and is the optimistic-concurrency token. All content/status writes go through the `wiki_save_page()` RPC (`security invoker`, so RLS still applies). It does a conditional `update … where revision = p_base_revision`, appends an immutable snapshot to `wiki_page_versions` (`kind` `save|publish|restore`, pre-151 rows are `publish` with `revision` null), and deletes the caller's own draft, all in one transaction. A stale base raises SQLSTATE `P0409`, which the routes map to **HTTP 409** `{ error:"conflict", current:{revision,updatedBy,updatedAt} }` via `src/lib/wiki/save-errors.ts`. `P0404` means not found and `42501` means a non-writer. `PATCH /api/wiki/pages/[pageId]` therefore **requires `baseRevision`** for title/content/tags/status (a `parentId`-only move skips it). Restore (`POST …/revisions/[revisionId]/restore`) re-saves a snapshot as a new `restore` revision, so it is itself undoable. `wiki_page_drafts` holds one autosaved draft per (page, user) with **owner-only RLS**. Other users learn *who* holds a draft only via the `security definer` `wiki_page_draft_holders()`, never the content. Live awareness is a single public Supabase Realtime channel `wiki-presence`: Presence tracks `{userId,name,email,pageId,mode,since}` and Broadcast sends `page-saved`. There is no DB table and no `realtime.messages` RLS (private-channel auth is a follow-up). The model is advisory with no hard locks. Real-time co-editing (Yjs) is explicitly deferred. The diff engine is `src/lib/wiki/diff.ts` (jsdiff `diff@9`, browser-only; output must be DOMPurify'd).
