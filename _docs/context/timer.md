# Timer breaks and Activity stream

Moved verbatim from CLAUDE.md. Read before working in this area.

- **Timer break expiry, break records & Activity stream** (task 439, migration 168 **written, not applied**) — a break's end is **server-authoritative**, never a browser tab's job. `reconcileTimer(row, nowMs)` (`src/lib/timer/reconcile.ts`, pure, checked by `_docs/task/439-timer-logic.check.ts` via `npx tsx`) returns the **backdated** transition for an expired break: `break_end` at `break_started_at + duration`, and the paused task/ticket timer resumes at that same instant (a break-only row is deleted). `loadReconciledTimer()` (`reconcile-apply.ts`) applies it with an `updated_at` optimistic token (two tabs never double-append; `_docs/task/439-reconcile-apply.check.ts`) and **every** `/api/v2/timer/*` route calls it first, so `break/cancel` is idempotent. The client only asks for it sooner (`timer-context.tsx` re-fetches `GET /api/v2/timer` when its countdown hits zero). **Deliberately no idle/inactivity or "app went quiet" detection** — people legitimately close the Hub and keep working, so a running timer is never auto-paused or capped; only pause/resume/break/stop events are recorded. `timer_breaks` keeps one durable row per break (incl. break-only), linked to `time_logs` on stop; its writes are best-effort so the app works before the migration lands. `BREAK_WARNING_MINUTES` + `use-break-chime.ts`/`chime.ts` play a Web Audio chime/toast 10 min (meal) or 5 min (coffee) before a break ends and a ring when it ends (mute toggle in the break panel). The per-log **Activity** panel (`projects/_shared/_timer-activity-trigger.tsx` + `_timer-activity-stream.tsx`, derivation in `src/lib/timer/activity.ts`) replaces the hover tooltip; the three `_timer-timeline-popover.tsx` files re-export it, and the live session shows in the header timer panel. **Editing a timer log's period** (task 440) recomputes hours with `workedHoursForPeriod()` (`src/lib/timer/period-hours.ts`, checked by `_docs/task/440-period-hours.check.ts`), used by all three time-log PATCH routes: recorded pauses/breaks (same state map as the Activity stream) that fall inside the new range are subtracted, time added beyond the recorded session counts fully, a same-length change (date move) keeps stored hours, a range fully inside pauses/breaks is a 400, and manual / timeline-less / Duration-mode logs keep the plain span. `time_logs.timeline` is never rewritten; the Activity panel shows "Period edited after recording" when its Worked total and the log's hours differ.
