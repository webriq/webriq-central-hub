# Inbound email ingestion

Moved verbatim from CLAUDE.md. Read before working in this area.

- **Inbound-email inline images** (`cid:`-referenced, e.g. Apple Mail screenshots) are resolved by pulling raw MIME over **read-only IMAP** (`src/lib/email/imap.ts`, tasks 321/322) — Zoho Mail's REST API doesn't expose them and the `/mail/ImageDisplay?...cid=...` src it returns needs an interactive webclient session. The `ZOHO_MAIL_IMAP_HOST` / `ZOHO_MAIL_IMAP_PORT` / `ZOHO_MAIL_IMAP_APP_PASSWORD` env trio is a **hard requirement in every deployed environment running the email-poll cron** — if absent, `getImapConfig()` returns `null` and inline-image resolution degrades to a no-op, leaving dead `/mail/ImageDisplay` `<img src>` in the stored `ticket_messages.body` (this was task 341's root cause: the trio was set locally but never on Vercel, so every prod-polled ticket for weeks shipped broken images with no log signal). Since task 341, `toParsedInboundEmail()` warns (`[inbound] unresolved inline image(s) …`) and stamps `source_meta.inlineImagesUnresolved` when this happens; `_message-html.ts`'s `neutralizeDeadInlineImages()` renders a placeholder instead of a broken-image box; and `POST /api/admin/desk/backfill-inline-images` (admin, `?dryRun`/`?limit`/`?ticketNumber`) retro-fixes already-stored messages.

- **Inbound-email regular attachments** (task 456) come from Zoho Mail's **Get Attachment Info** endpoint (`/messages/{id}/attachmentinfo`, `getAttachmentInfo()` in `src/lib/zoho/mail.ts`), **not** `/content` — `/content` returns only the body, and reading attachments from it silently stored zero attachments for every polled email until task 456. Files are stored by `storeEmailAttachments()` (`src/lib/email/attachments.ts`, shared by `email-poll` and the backfill) into `ticket-attachments` as `attachments` rows (`entity_type='inbox_message'`, `external_id` = Zoho attachmentId, `cid` null). `POST /api/admin/desk/backfill-email-attachments` (admin, `?dryRun`/`?limit`/`?ticketNumber`) fills older client messages and stamps `source_meta.attachmentsBackfilledAt` so they aren't re-checked; a Zoho error (message moved out of INBOX/deleted) is reported in `unresolved` and left unstamped. Sent-folder staff replies (`sent-ingest.ts`) still don't ingest attachments.
